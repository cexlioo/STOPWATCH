# TTBike 骑行码表

基于 **STM32F103C8T6 + FreeRTOS** 的智能骑行码表。支持 GPS 定位、温湿度采集、OLED 实时显示、外置 SPI Flash 骑行记录滚动存储，并通过 4G 模块把骑行数据以 JSON 形式上报到云端服务器；同时提供串口命令查询、按场次导出历史骑行数据的功能。

## 功能特性

- **实时骑行数据**：速度、里程、骑行时长、最大/平均速度、卡路里、实时温湿度
- **GPS 定位**：解析 NMEA-0183 的 `$GNRMC` 语句，UTC 时间自动换算北京时间，经纬度转换为 GCJ-02（高德）坐标系
- **本地持久化**：外置 W25Q16 滚动存储，每 10 秒记录一条轨迹点，13 条组成一页（130 秒），落盘带写标志，断电可恢复
- **索引双备份**：索引双扇区交替写 + 版本号 + 写标志，掉电不会丢索引、不会读到错误的表
- **4G 联网**：M100P 模块 AT 指令初始化、注网、PDP 激活、TCP 长连接、透传收发
- **云端交互**：每 2 秒上报一次 JSON 数据，每 180 秒向服务器请求时间同步
- **串口交互**：USART1 支持 `get data` 列出历史场次、输入编号导出对应场次的完整轨迹
- **分级日志**：线程安全的 4 级日志（DEBUG/INFO/WARN/ERROR），可编译期裁剪

## 硬件组成

| 模块 | 器件 | 接口 | 说明 |
|---|---|---|---|
| 主控 | STM32F103C8T6 | — | Cortex-M3，72 MHz，64 KB Flash / 20 KB SRAM |
| 外部存储 | W25Q16（2 MB） | SPI | 骑行记录 + 索引 |
| 温湿度 | AHT10 | I2C | 实时温度、湿度 |
| 显示 | 0.96" OLED（SSD1306） | I2C | 三屏界面：欢迎、骑行数据、统计信息 |
| 定位 | GPS 模块 | USART3（9600） | NMEA-0183 输出 |
| 联网 | M100P 4G 模块 | USART2（115200） | AT 指令 + 透传模式 |
| 调试 | 串口 | USART1（115200） | 日志输出、数据查询与导出 |
| 交互 | 2 个按键 | EXTI | KEY1 切换骑行状态，KEY2 切换显示界面 |

## 软件架构

### 分层设计

```
应用层      bike.c / screen.c          骑行状态机、界面、云端交互业务
存储层      flash_data.c / flash_index.c   记录读写、索引双备份
模块驱动层  GPS / AHT10 / OLED / W25Qxx / at_M100p
AT 抽象层   at_interface.c     通用 AT 指令收发与响应匹配
缓冲层      ringbuffer.c       接收环形缓冲区
硬件层      usart.c / spi_xx.c / i2c_xx.c / stm32f10x_it.c
```

AT 指令部分额外拆成「通用接口层」和「模块封装层」：换一个 4G/WiFi 模块，只需按同样接口新写一份 `at_XXX.c`，上层的 `at_execute()`、环形缓冲区、业务层都不用动。

### FreeRTOS 任务划分

| 任务/对象 | 优先级 | 职责 |
|---|---|---|
| `bike_task` | 3 | 阻塞在任务通知上，按位分派按键、GPS、服务器连接、时间同步、数据导出等事件 |
| `at_task` | 默认 | 4G 模块生命周期管理：连接服务器、透传发送、接收回调、断开清理 |
| 软件定时器（1 s） | — | 刷新 OLED、累计骑行数据、每 10 s 存一条记录、每 2 s 上报 |
| 各外设中断 | — | 按键 EXTI、USART1/2/3 |

跨任务通信全部使用**任务通知**：事件用 `xTaskNotify(..., eSetBits)` 按位发送，一个 32 位通知值就是一张事件位图；需要携带数据的发送则用链表队列 `cmd_queue` 传递字符串、通知只做「叫醒」。中断里统一使用 `xTaskNotifyFromISR + portYIELD_FROM_ISR`。

## Flash 存储设计

W25Q16 共 2 MB，划分为：

```
0x0000 ~ 0x0FFF   索引备份 0
0x1000 ~ 0x1FFF   索引备份 1
0x2000 ~ ...      16 张数据表（每张 31~32 个 4 KB 扇区）
```

- **索引**（76 字节）：已写入表数量、下一张表下标、16 张表的开始时间戳、版本号、写标志；
- **记录页**（256 字节）：13 条轨迹点（经度 double + 纬度 double + 速度 uint16，共 234 字节）+ 骑行状态（20 字节）+ 写标志 `0xA5`；
- **容量**：一页 130 秒，单张表约 17.91 / 18.49 小时，16 张表循环覆盖，合计可存十几小时骑行记录；
- **掉电保护**：索引双扇区交替写、版本号选大、写标志 `0xA5` 校验，写入一半的页会被判定为无效数据。

## 通信协议

设备与云端之间使用 TCP 长连接 + JSON：

**数据上报（每 2 秒）**

```json
{
  "cmd": "upload data",
  "name": "dev_bike_kieran",
  "type": "bike",
  "time": 1767000000,
  "data": {
    "temp": 26.50, "humidity": 55.20,
    "speed": 18.30, "distance": 12.40,
    "total_time": 3600, "max_speed": 32.10,
    "average_speed": 15.60, "kcal": 320.50,
    "lat": 23.123456, "lng": 113.567890
  }
}
```

**时间同步（每 180 秒）**

```
上行：{"cmd":"time request"}
下行：{"cmd":"time response","time":1767000000}
```

## 编译与烧录

1. 安装 **Keil MDK 5** 及 STM32F1 系列器件支持包；
2. 打开 `Project.uvprojx`，确认目标芯片为 `STM32F103C8`；
3. 编译（F7）后通过 ST-Link / J-Link 下载；
4. 重新编译前可运行 `keilkill.bat` 清理 `Objects`、`Listings` 等产物；
5. 上电后 OLED 显示欢迎界面，GPS 定位有效后按 KEY1 开始骑行并自动连接服务器。

> 注意：4G 服务器 IP/端口、高德地图 Key 等与个人环境相关的参数需要自行修改后再编译。

## 已知限制与后续计划

- **无心跳与断线重连**：进入隧道断网后应用层无法感知，目前依赖重新按键重连；
- **上传无断点续传**：断网期间数据虽已落盘 Flash，但恢复连接后不会自动补传，计划按「页」为单位从 Flash 读取补传，服务器侧按 `(device, table_ts, page_no)` 做幂等去重；
- **环形缓冲区满时静默丢字节**：只打印日志，没有溢出计数与上层通知；
- **AT 抽象层耦合 `usart2`**：通用层直接依赖具体串口，可抽象成收发回调以提升可移植性。
